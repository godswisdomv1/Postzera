# Postzera decisions log

Pivots and upgrades since the master blueprint (`docs/blueprint.md`), in order.
Where this file and the blueprint disagree, this file wins.

## Process
- D01 Claude builds in a sandbox and pushes through the GitHub API. Termux is only for viewing/cloning (its Flutter is 3.29; blueprint needs 3.47.7).
- D02 `check.yml` runs on every push (pub get, gen-l10n, analyze, test, layer checks). Blueprint forbade `push:` triggers; build workflows stay manual-only.
- D03 `app/tool/check_layers.sh` replaces the blueprint's `! grep` lines (they never fail a CI step). Also fails on TODO/FIXME/UnimplementedError.
- D04 `app/tool/ci_step.sh` republishes step output as annotations, because job logs are unreadable from the sandbox. It keeps the lines before a failing test, and Gradle "What went wrong".
- D05 Tests land in the same batch as the code. Utility tests came in Batch 1.
- D06 Signing alias is `Postzera` (not `postzera-upload`). Keystore made in the sandbox; the four secrets were written through the API.
- D07 Version policy: adopt newer packages when better for the product, with a changelog check at the start of each batch (not blind pins).
- D08 Play account is personal. Generated media carries no mark until the user picks from samples.

## Design and behaviour
- D20 Models: 18 error kinds (share and purchase errors kept separate); reminders default on, 09:00; all nine platforms enabled; X, Facebook, Pinterest use inline hashtags; mediaBodyMaxChars 220 (Instagram, Facebook, LinkedIn) and 600 (TikTok).
- D21 Ports changed from the blueprint: overlays are a timed list (hook first 4 s, CTA last 3 s); `showPrivacyOptions` returns the new consent answer; FileStore can stat and delete a post's output only; notifications have `launchTap`.
- D22 Pipeline: cache key is in the output file name (a cache hit = file exists). Video source always gives video, even on image-only platforms.
- D23 Storage: true upsert (never INSERT OR REPLACE, which would cascade-delete send records); `quick_check` at start; ids sanitized in file names.
- D24 Clips are reframed with a single-layer composition on an exact-size canvas from the start. Slide videos: 24 fps, 4 Mbps. Clips: 30 fps, 8 Mbps.
- D25 Consent follows Google's `canRequestAds` only (no app override). Declined users may still get limited ads. After a changed privacy choice the banner is dropped and requested again.
- D26 Production banner ids come from build defines `ADMOB_ANDROID_BANNER` / `ADMOB_IOS_BANNER`; if absent, no ad is requested.
- D27 Standard adaptive banner kept (Google's large anchored banner would break the 90 dp cap).
- D28 UI additions: tokens `wordmark`, `accentTint`, opacities, sheet/switch/wheel sizes; `PzSystemUi` (system-bar colors per theme); `PzTextField` uses the selection gesture builder with `rendererIgnoresPointer: true` (otherwise EditableText's own handlers win and no toolbar appears) and `TextSelectionControls with TextSelectionHandleControls`.
- D29 Widgets may import `l10n/` and `core/providers`; `l10n/localized_text.dart` maps errors, banners, undo labels to strings.
- D30 Dev tools (`lib/dev/`): gallery + media lab. Media lab uses unique output ids and clears its output folder per run (earlier 2-3 ms results were cache hits). Both pages stay alive (IndexedStack).
- D31 Extra CI: `smoke_android.yml` (installs a built APK on an emulator, reports crash log), `device_test.yml` (integration test of the real screens on an emulator), `inspect.yml` (reads package APIs), `scaffold.yml` (flutter create, finalize, brand, upgrade).

## Screens (Batch 16)
- D40 Screens read providers through `ScreenServices` / `ServicesScope` (`lib/screens/screen_services.dart`). The shell's `AppServices` implements it; tests use `test/screens/test_services.dart` (real providers on in-memory fakes). Route names and typed args are in `lib/screens/routes.dart`. Screens navigate by route name.
- D41 `PzScreen` is the frame of every screen (page color, nav bar, 600 dp content, fixed bottom area on the safe area). `PzRow` gained a `leading` widget; `PzIcons` gained `more` and `search`.
- D42 Queue: empty state offers Import only (the fixed New post button is already there; the blueprint's duplicate button was dropped). The quiet Remove ads row sits above the banner, shown only while a banner is visible.
- D43 Queue post cards: tapping the header opens the variants; each platform row opens its send screen; status chip Posted or Skipped.
- D44 Library: rows grouped by day inside one card per day; row menu is a bottom sheet (Edit, Preview and send, Duplicate, Delete with confirmation and undo). Search debounced 250 ms.
- D45 Composer: counters use the shortest caption limit among enabled platforms that use that slot. Draft autosaves; leaving an unsaved empty post discards it (`PopScope`).
- D46 Variants: opened by post id; reuses the composer's variants when it is the same post, otherwise loads the post and builds. A draft shows Schedule (primary) and Send now; other posts show Send now. Tapping a card saves a draft first, then opens Send.
- D47 Send: the paste hint is always shown (no one-time flag exists in settings). `SelectableText` is Material, so captions use plain `Text` with copy buttons. The mark-as-posted sheet is not dismissible by the scrim.
- D48 Section headers render in capitals (`PzSectionHeader`), so tests look for the capitalized text.
- D49 Widget tests must scroll to items below the fold (`reveal` helper) and wrap tests in `screenTest` so banner and undo timers expire.
